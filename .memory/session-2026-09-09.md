## FjordLauncher findings

- FjordLauncher is a Prism Launcher fork with Flatpak application ID:
  `org.unmojang.FjordLauncher`
- It can be installed with:
  `flatpak install --user https://unmojang.github.io/unmojang-flatpak/org.unmojang.FjordLauncher.flatpakref`
- A PRIME-offload test launch is:
  ```bash
  env \
    __NV_PRIME_RENDER_OFFLOAD=1 \
    __GLX_VENDOR_LIBRARY_NAME=nvidia \
    __VK_LAYER_NV_optimus=NVIDIA_only \
    flatpak run org.unmojang.FjordLauncher
  ```
- Persistent Flatpak overrides can be set with:
  ```bash
  flatpak override --user org.unmojang.FjordLauncher \
    --env=__NV_PRIME_RENDER_OFFLOAD=1 \
    --env=__GLX_VENDOR_LIBRARY_NAME=nvidia \
    --env=__VK_LAYER_NV_optimus=NVIDIA_only
  ```
- These launcher settings are only useful after the host NVIDIA driver is functioning (`nvidia-smi` must work).

## Recommended image strategy

Do not directly replace the current deployed custom image with an unverified, guessed legacy image reference. A direct rebase to an official Bazzite image would also discard custom image-layer changes, although rpm-ostree rollback can return to the previous deployment.

The repository is ready for a second image such as:

`images/bazzite-workstation-legacy-nvidia/`

That image should:

1. Reuse `packages/image-common/`.
2. Have its own Containerfile and disk configs.
3. Use the exact Bazzite base that supplies/selects the compatible proprietary legacy NVIDIA driver branch.
4. Be added to both build matrices.

Do not merely duplicate the current Containerfile under a new name: that would still ship the same NVIDIA `610.57.04` branch and would not solve a Pascal/GP107 compatibility problem.

## Validation commands

After booting a candidate image:

```bash
nvidia-smi
/usr/libexec/nvidia-legacy-hardware; echo $?
uname -r
rpm -qa | grep -E '^nvidia|^akmod'
journalctl -b -k | grep -iE 'nvidia|nouveau|firmware' | tail -100
```

`/usr/libexec/nvidia-legacy-hardware` should return exit code `0` for the GTX 1050 Mobile.
